The mechanic worth understanding: findings generate model-specific guardrails. Validation output isn't just a report — it becomes the runtime policy. That loop is the core of the product's design and the main argument for buying validation and runtime together rather than separately.

The hybrid connector runs over a bidirectional gRPC stream encrypted with TLS. The connection is initiated only from the data plane — there are no outbound connection requests from the control plane, and outbound TCP 443 is the only firewall rule required.

Agent-specific threats named in the documentation

ThreatWhat it looks like
Memory poisoningCorrupting an agent's persistent context so later decisions are shaped by planted content
Tool misuseUsing a legitimately available tool for something outside its intended purpose
Privilege escalationAn agent acquiring or exercising access beyond what it was granted
Intent hijackingRedirecting an agent's goal mid-task, typically through injected instructions
Deceptive agent behaviourAn agent misrepresenting what it did or intends to do
Harmful action chainsIndividually permissible tool calls that compose into a damaging sequence

These matter for scoping because they are behavioural, not access-control, problems. Authorization decides whether a call is allowed; these are about whether an allowed call is legitimate. AI Defense is the behavioural half — pair it with identity controls for the other half.

Quick answers

Do I need to change my application to use AI Defense?For the gateway, yes — you repoint the model URL at the AI Defense gateway. For the Inspection API, you add an explicit call and handle the verdict. Through Multicloud Defense, no change to the app.
Can I run validation against a model that isn't exposed to the internet?Yes, with a hybrid deployment. That's the main reason the VPC and AI POD data planes exist — the model being tested never needs to be publicly reachable.
Does supply chain scanning come with every tier?No. Model and MCP scanning is Advantage only. Plan for that early — it's the component most likely to be assumed included.
How do validation and runtime relate?Validation findings generate model-specific guardrails that runtime then enforces. Buying only one gets you half the loop.
Where does shadow AI fit?Two different problems. Rogue AI assets in your own cloud are AI Cloud Visibility. Employees using third-party AI apps is Cisco Secure Access, surfaced through Application Discovery.
What is the lineage?AI Defense is built on Robust Intelligence, founded 2019 in San Francisco, with Cisco's intent announced August 2024 and the deal closing around September 2024. The same technology also underpins Cisco Foundation AI.

Glossary

AI BOM
AI Bill of Materials — inventory of AI software assets including MCP servers and third-party dependencies. Has its own CLI
Algorithmic red teaming
Automated adversarial testing that replaces weeks of manual red teaming, running 200+ techniques
Adaptive red teaming
Multi-turn testing that adjusts its approach based on the model's responses, as opposed to standard single-pass testing
Application / connection
AI Defense's object model — an application holds one or more connections, each representing an LLM API being protected
Policy Studio
Where runtime policies are authored, above the individual guardrails and rules
DLP profile
The data-classification set a privacy guardrail enforces — PII, PCI, PHI, source code, model information
Hybrid connector
The component installed in your cluster that links your data plane to Cisco's control plane
MCP
Model Context Protocol — how agents reach tools and data. Scanned pre-deployment and enforced at runtime
Risk profile
Per-asset scoring from supply chain scanning that drives allowlist and blocklist decisions
Validation target
The model, application or agent a validation run tests against
Custom goal
A domain-specific objective you add to a validation run beyond the built-in categories
UPI
User Provisioned Infrastructure — the OpenShift model used when the control plane runs as VMs on your vSphere
SCC
Security Cloud Control — the Cisco console AI Defense is reached through

Where to be careful

  • The gateway is a traffic path change. Repointing a production application's model URL is a real change with a real rollback plan. Monitor mode first, always.
  • The Inspection API doesn't block. Teams choose it because it's less invasive, then assume they have enforcement. They have a verdict; the enforcement is code they still have to write.
  • Advantage tier gates supply chain. The single most common scoping surprise.
  • On-prem installs are a project, not a task. OpenShift 4.18+, three control plane nodes, two workers, GPU and Ingress operators, DNS, certificates. Treat it like the infrastructure build it is.
  • Sizing is per request rate, not per user. The published figures assume 5 req/s at 2.5k tokens per application. Model your own token sizes before choosing a size.
  • The user guide is behind SSO. Screen-level detail here is inferred from the data sheet and the guide's structure. Confirm field names before writing a runbook.
